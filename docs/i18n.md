# Internationalisation (i18n)

Objectif : l'application s'adapte automatiquement à la langue de l'utilisateur, partout dans le monde.
Langues prises en charge : français (`fr`, langue source), anglais (`en`), arabe (`ar`, de droite à gauche), espagnol (`es`), portugais (`pt`).

**État :** phase A (moteur) terminée. Phase B en cours : groupe 1 (accueil, connexion, inscription, mot de passe oublié) branché ; groupes 2 (expéditeur) et 3 (GP) à faire. Plan complet : A moteur, B application (par groupes de pages), C backend (erreurs et notifications), D site vitrine, E contrôle qualité.

| Page | Langues branchées |
|---|---|
| `index.html` (accueil, choix du profil) | fr, en, ar, es, pt |
| `connexion.html`, `inscrire.html`, `oublie.html` | fr, en, ar, es, pt |
| `pwa.js` (bannière d'installation, notifications) et bouton Google (`gauth.js`) | fr, en, ar, es, pt |
| Autres pages | français seulement (moteur non chargé) |

Les messages d'erreur renvoyés par l'API (`error`, `message`) restent en français tant que la phase C n'est pas faite : ils s'affichent tels quels dans les alertes.

## Choix de la langue

Dans cet ordre (`frontend/i18n.js`, `resolveLanguage`) :

1. Le choix de l'utilisateur, mémorisé dans `localStorage` (`sengpLang`).
2. La langue de l'appareil (`navigator.languages`), si elle est prise en charge. Exemple : `pt-BR` donne `pt`.
3. Sinon, la langue du pays déduit du **fuseau horaire** (`Intl`). Exemple : un appareil en allemand à `Europe/Madrid` donne `es`. La table `COUNTRIES` couvre les pays francophones, arabophones, hispanophones et lusophones.
4. Sinon, l'anglais.

Aucune adresse IP n'est lue et aucun service externe n'est appelé. Conséquence assumée : un téléphone réglé en anglais, utilisé au Sénégal, reste en anglais tant que l'utilisateur n'a pas choisi une autre langue. Le sélecteur de langue (`SengpI18n.mountSwitcher(élément)`) permet de changer à tout moment.

Un fuseau absent de la table (par exemple `Asia/Tokyo`) ne déclenche aucune erreur : on retombe sur l'anglais. Pour ajouter un pays dont la langue est prise en charge, compléter `COUNTRIES` (le test vérifie la langue et l'unicité des fuseaux).

## Utiliser le moteur dans une page

```html
<script src="api.js"></script>
<script src="i18n.js"></script>

<h1 data-i18n="home.title">Bienvenue</h1>
<input data-i18n-attr="placeholder:common.search; title:common.close" placeholder="Rechercher">
```

```js
sengpT('errors.generic');                     // texte brut
sengpT('errors.expediteur_only', { type: 'GP' });
sengpT('mission.count', { count: 3 });        // pluriel
SengpI18n.fmt.currency(15000);                // « 15 000 FCFA » (chiffres latins dans toutes les langues)
SengpI18n.fmt.date(m.created_at);             // date selon la langue
SengpI18n.fmt.dateTime(m.created_at);
SengpI18n.lang;  SengpI18n.dir;               // 'ar' / 'rtl'
await SengpI18n.ready;                        // traductions appliquées
window.addEventListener('sengp:languagechange', ...);
```

Règles :

- Le texte écrit dans la page reste le **français** : c'est la valeur par défaut tant que les traductions ne sont pas chargées, et la page reste lisible hors ligne ou si un dictionnaire ne se charge pas.
- Les traductions sont insérées comme **texte** (`textContent`), jamais comme HTML. Une valeur ne doit pas contenir `<` ni `>` (un test l'impose). Pour du texte structuré, découper en plusieurs clés.
- Une clé absente d'une langue retombe sur l'anglais, puis sur le français, puis s'affiche telle quelle (et apparaît dans `SengpI18n.missing`).
- Le nom `sengpT` (et non `t`) évite toute collision avec les variables locales des pages.
- Les montants restent en **FCFA** (paiements Wave et Orange Money). Seuls les séparateurs et les dates changent selon la langue.

## Fichiers de langue

`frontend/locales/<langue>.json`, à plat : `"section.cle": "texte"`.

- Nommer par écran puis par usage : `home.title`, `payment.method.cod`, `errors.network`.
- Variables : `{nom}`. Elles doivent être identiques dans toutes les langues (sauf formes de pluriel : voir ci-dessous).
- Pluriels : `cle.one`, `cle.other`, et pour l'arabe `zero`, `one`, `two`, `few`, `many`, `other`. Les formes numérotées peuvent omettre `{count}` quand le nombre est implicite (« شحنة واحدة »). `cle.other` est obligatoire dans chaque langue.
- Après modification : `cd frontend && npm test`. Les tests vérifient que les cinq langues ont les mêmes clés, que les variables correspondent, que les pluriels sont complets (0 à 200) et que chaque statut de mission de la base a sa traduction.

### Ajouter une langue

1. Créer `locales/<code>.json` avec toutes les clés du français.
2. Ajouter le code à `SUPPORTED`, `NATIVE_NAMES` et `LOCALE_TAGS` dans `i18n.js`, ainsi que les pays dans `COUNTRIES`.
3. Si la langue s'écrit de droite à gauche, l'ajouter à `RTL`.
4. Compléter `tests/i18n.test.js` si besoin.

## Brancher une page (procédure de la phase B)

1. Dans `<head>` : `<script src="api.js">`, puis `<script src="i18n.js">`, puis `<link rel="stylesheet" href="i18n.css">`.
2. Ajouter `data-i18n="cle"` aux éléments de texte, `data-i18n-attr="placeholder:cle; aria-label:cle"` aux attributs. Le texte français reste dans la page.
3. Phrase avec lien dont l'ordre varie : `<span data-i18n-rich="cle">Texte {lien}</span>` avec, à l'intérieur, l'élément portant `data-slot="lien"` (et son propre `data-i18n`). Le modèle de la clé contient `{lien}`.
4. Dans les scripts : `sengpT('cle', { variable })` à la place des textes en dur. Pour un libellé modifié par le script (bouton, texte d'état), mémoriser aussi sa clé avec `el.setAttribute('data-i18n', cle)` : il suit alors un changement de langue.
5. Ajouter `<div data-i18n-switcher></div>` pour le sélecteur de langue.
6. Ajouter le bloc `[dir="rtl"] …` : éléments positionnés en absolu (`left`/`right`), `padding`/`margin` d'un seul côté, flèches (`transform: scaleX(-1)` ou classe `i18n-flip`).
7. Les tests `tests/pages-i18n.test.js` vérifient ensuite : clés présentes dans les cinq langues, texte français de la page identique à `fr.json`, syntaxe des scripts, plus aucun `alert()` en français en dur.

Les captures d'écran de contrôle se font en navigateur sans écran : `msedge --headless=new --lang=ar --window-size=500,900 --screenshot=… http://localhost:8766/connexion.html` (largeur minimale 500 px).

## Droite à gauche (arabe)

Le moteur pose `lang` et `dir="rtl"` sur `<html>` dès la détection. La mise en page des pages (marges, alignements, icônes directionnelles) reste à adapter page par page avec des propriétés logiques CSS (`margin-inline-start`, `text-align: start`…) : c'est un travail de la phase B, à vérifier visuellement.

## Textes juridiques

Les CGU, la politique de confidentialité et les mentions légales ne sont **pas** traduits tant qu'un juriste n'a pas validé chaque langue. Ils restent en français, avec un bandeau d'explication.
